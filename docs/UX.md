# UX 가이드라인: 원칙과 퍼널

Figma "[UI Design Principles](https://www.figma.com/ko-kr/resource-library/ui-design-principles/)"의 7원칙(계층 구조·점진적 공개·일관성·대비·접근성·근접성·정렬)을 FinSight에 맞게 구체화한 문서다.

**이 문서가 정하지 않는 것**: 색·간격·타이포·컴포넌트 치수는 `docs/DESIGN.md`가 기준이다. 여기서는 그 토큰을 **어떤 화면 흐름과 판단 기준으로 배치하는지**만 다룬다. 라우트 구조는 `docs/ARCHITECTURE.md`, 기능 범위는 `docs/PRD.md`를 따른다.

PRD의 사용 리듬이 이 문서 전체를 관통한다: **사용자는 한 달에 한 번 들어온다.** 매번 처음 쓰는 것처럼 느껴지므로, 설명 없이 이해되지 않는 화면은 실패다.

## 7원칙 → FinSight 적용

### 1. 계층 구조 (Hierarchy)
크기·굵기·색·간격으로 "뭘 먼저 봐야 하는지"를 알려준다.

- 대시보드는 총 지출 숫자가 화면에서 가장 크다. 인사이트는 `01 · 02 · 03`으로 번호를 매겨 "가장 중요한 변화가 첫 번째"임을 명시한다.
- 랜딩은 헤드라인 1개 + 보조문 1개 + CTA 2개(주/보조)로 끝낸다. 문단을 늘려 설명하지 않는다.

### 2. 점진적 공개 (Progressive Disclosure)
한 번에 다 보여주지 않고 필요한 시점에 필요한 만큼만 보여준다.

- 업로드 처리(파일 읽는 중 → 컬럼 찾는 중 → 분류 중 → 집계 중)는 단일 스피너가 아니라 4단계를 순차 노출한다. "AI가 지금 뭘 하는지"를 보여줘야 30초 안팎의 대기를 견딜 만하게 만든다 — ADR-003의 배치 진행률 원칙을 UI로 옮긴 것이다.
- 요금제는 Free/Pro 두 카드로 끝낸다. 컬럼 수동 지정 같은 고급 옵션은 아예 없앤다(PRD MVP 제외) — 있으면 공개할 단계가 아니라 만들지 않을 기능이다.
- 파싱 실패는 "어떤 컬럼을 못 찾았는지"만 보여준다. 원인 전체를 나열하지 않는다.

### 3. 일관성 (Consistency)
같은 패턴은 어디서나 같은 방식으로 동작한다.

- 포인트 컬러(`--accent`)는 모든 화면의 primary CTA·활성 nav 상태에만, 딱 하나로 쓰인다.
- 사이드바는 **대시보드 · 거래 · 추이** 세 개로 고정한다. 화면마다 순서나 이름을 바꾸지 않는다.
- shadcn/ui + 디자인 토큰(`design/_ds/*/tokens`)을 경유한다. 컴포넌트마다 radius·spacing을 새로 판단하지 않는다.

### 4. 대비 (Contrast)
중요한 동작과 부수적인 동작을 시각적으로 분리한다.

- 화면당 accent 채움 버튼(primary)은 핵심 동작 하나에만 쓴다. 나머지는 secondary(outline)로 내린다 — 랜딩의 "명세서 올려보기"(primary) vs "예시 대시보드 보기"(secondary)가 기준 사례다.
- `LockVeil`은 잠긴 콘텐츠를 흐리게 하되 "Pro로 업그레이드" 버튼만 선명한 accent로 남긴다. 잠금과 탈출구를 동시에 대비시킨다.

### 5. 접근성 (Accessibility)
색·명도·인터랙션이 모든 사용자에게 인식 가능해야 한다.

- 다크 모드 고정이라 팔레트가 하나뿐이다. 라이트 대체판으로 도망갈 수 없으므로, accent 값 확정 시 WCAG AA 대비 검증을 **반드시** 거친다.
- 포커스 링(`--shadow-focus` 토큰)을 인터랙티브 요소에서 생략하지 않는다.
- 업로드는 드래그앤드롭에만 의존하지 않는다. "파일 선택" 버튼을 항상 동일한 비중으로 제공해 키보드·스크린리더 경로를 남긴다.

### 6. 근접성 (Proximity)
관련 있는 요소는 붙이고, 무관한 요소는 떼어놓는다.

- 업로드 드롭존 바로 아래 프라이버시 설명(`PrivacyList`)을 둔다. "이 파일이 안전한가"라는 불안이 생기는 바로 그 지점에서 해소한다.
- 인사이트는 근거가 되는 카테고리·기간을 클릭하면 거래 테이블이 그 조건으로 필터링되어 열린다(ARCHITECTURE.md LLM 전송 경계). 공간적 근접 대신 **인터랙션으로 근접성**을 만든 사례다 — LLM #3이 개별 거래를 보지 못해도, 클릭 한 번으로 사용자는 "식비가 32% 늘었다"의 근거를 확인한다.

### 7. 정렬 (Alignment)
그리드로 예측 가능한 리듬을 만든다.

- 랜딩·대시보드 모두 같은 최대 폭 중앙 정렬 그리드를 공유한다.
- 금액은 항상 monospace + 우측 정렬(DESIGN.md). 거래 테이블·범례·StatCard의 숫자 열이 화면이 달라도 같은 세로선에 맞는다.

## 유저 퍼널: 유치부터 재방문까지

퍼널의 각 단계는 이탈 지점이자 원칙 적용 지점이다. 표는 화면을 새로 만들거나 고칠 때 "이 단계에서 뭘 지켜야 하는지"의 체크리스트로 쓴다.

| 단계 | 화면/라우트 | 목표 | 핵심 원칙 | 규칙 |
|---|---|---|---|---|
| 1. 발견 | `app/page.tsx` | 3초 안에 "이게 뭔지, 나한테 왜 필요한지" 전달 | 계층 구조 | 헤드라인 1개, CTA 2개(주/보조). "신용카드 등록 없이 시작" 같은 마찰 제거 문구를 CTA 바로 아래 붙인다 |
| 2. 신뢰 확보 | 랜딩 프라이버시 섹션 | "내 카드 내역을 AI에 보낸다"는 거부감 해소(PRD 1차 전환 장벽) | 근접성·일관성 | 업로드 화면과 **같은 문구**(PrivacyList)를 재사용한다. 랜딩·업로드 어디서 봐도 같은 약속이어야 신뢰가 쌓인다 |
| 3. 가입 | `app/login/` | 이탈 없이 계정 생성 | 점진적 공개 | 필드 최소화. 이 화면은 프로토타입에 없는 공백이다(DESIGN.md) — 새로 만들 때 랜딩과 같은 톤·토큰을 쓴다 |
| 4. 첫 업로드 | EmptyState → Upload | 업로드가 진입장벽이 되지 않게 | 점진적 공개·접근성 | 드래그앤드롭과 파일 선택을 동시에, 같은 비중으로 제공한다 |
| 5. 첫 결과(Aha 모먼트) | Upload 완료 → Dashboard | 업로드 직후 가치를 즉시 체감 | 계층 구조 | 총 지출 숫자가 가장 크고 가장 먼저 렌더된다. 도넛+범례가 로딩 스피너 없이 즉시 보여야 한다 |
| 6. 분류 신뢰 구축 | 거래 테이블 | 자동분류를 믿거나 쉽게 고치게 | 대비·근접성 | 카테고리 수정 UI는 항목 바로 옆에 둔다. "고친 내용은 다음 달에도 유지된다"(ADR-006)를 수정 시점에 안내한다 |
| 7. 인사이트 소비 | Insight 카드 | "그래서 뭘 알아야 하는지" 결론 제공 | 계층 구조 | 번호 매긴 인사이트. 클릭 시 근거 거래로 드릴다운 |
| 8. Pro 전환 유도 | LockVeil, 추이 탭 | Free 사용자가 Pro 가치를 미리 보게 | 대비 | 잠긴 영역은 완전히 숨기지 않고 흐리게 티저한다. 랜딩·가격 섹션에는 샌드박스 테스트 카드 번호(PRD)를 안내해 결제 없이 체험하게 한다 |
| 9. 재방문(한 달 후) | Dashboard | 설명 없이 "저번에 그거"를 바로 이해 | 일관성 | 레이아웃·용어·아이콘 위치를 절대 바꾸지 않는다. 신규 유저용 툴팁·안내 배너가 재방문자에게 반복 노출되어 방해하지 않게 한다 |

## 하지 말아야 할 것

- **조작된 사회적 증거를 넣지 않는다** — 가짜 후기, 부풀린 가입자 수, "방금 OO님이 가입했어요" 팝업. 포트폴리오 데모라는 이 프로젝트의 정직성 전제(PRD)와 배치된다.
- **다크패턴을 쓰지 않는다** — Pro 해지를 어렵게 만들거나 공포 조성 문구로 압박하지 않는다. Free로 떨어져도 데이터는 잠그기만 하고 지우지 않는다는 사실을 그대로 전달한다(PRD 요금제).
- **라이트 모드 토글, 두 번째 포인트 컬러, 손으로 그린 아이콘을 추가하지 않는다** — DESIGN.md 규칙 위반이다.
- **"결제 확인 중" 같은 대기 상태를 숨기지 않는다** — 웹훅 지연으로 잠깐 Free로 보이는 구간(ADR-007)을 배너로 명시한다. 침묵하면 사용자는 결제가 실패했다고 오해한다.

## 새 화면을 만들 때 빠른 체크

1. 이 화면에서 accent 채움 버튼이 두 개 이상인가? → 하나로 줄인다(대비).
2. 처음 보는 사용자가 3초 안에 다음 행동을 알 수 있는가?(계층 구조)
3. 한 달 후 재방문한 사용자가 이 화면을 보고 헤매지 않는가?(일관성)
4. 불안이 생기는 지점(업로드, 결제, Pro 잠금) 바로 옆에 그 불안을 해소하는 문구가 있는가?(근접성)
5. 키보드만으로 핵심 동작을 완료할 수 있는가?(접근성)
